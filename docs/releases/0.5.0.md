# Elementor JSON Bridge 0.5.0

This draft release packages the tagged, CI-validated source as a runtime-only WordPress plugin ZIP. Publish it only after the staging and browser gates below pass on this exact artifact.

## Highlights

- Discover and synchronize editable WordPress content after one private GitHub connection.
- Use a versioned content envelope for WordPress fields, taxonomies, ACF, selected Yoast fields, safe registered metadata and existing Elementor documents.
- Create new WordPress content through idempotent request files; new items remain drafts.
- Preserve conflict detection, capability checks, integrity-checked snapshots, verified readback and rollback.

## Supported versions

- WordPress 6.8 or newer; CI covers WordPress 6.8.3 and 7.1.
- PHP 8.1 through 8.5.
- Elementor 4.2.3 and Advanced Custom Fields 6.8.9 in both runtime matrices.
- Yoast SEO 28.3 in the WordPress 7.1 runtime matrix; fields are synchronized only when they are in the documented allowlist.

## Required checks before publication

- Test the exact ZIP on a clean staging site and verify installation plus update behavior.
- Verify a real private GitHub Device Flow connection and least-privilege repository access.
- Verify Elementor Pro Theme Builder condition resolution where that feature is claimed.
- Verify authenticated wp-admin appearance, keyboard focus and screen-reader behavior.
- Confirm snapshot restoration and verified readback on the intended staging plugin combination.

## Known limitations

- GitHub synchronization supports private content repositories only.
- The bridge manages editable content, not arbitrary options, users, credentials, orders, payment data or database tables.
- New content requests create drafts and do not invent a new Elementor layout.
- ACF, Yoast and registered metadata are limited to fields that pass the documented identity, permission and visibility rules.
- WP-Cron polling is request-driven and therefore targets, but does not guarantee, a one-minute cadence.
- Plugin combinations and content models not represented by CI require staging-first validation.
